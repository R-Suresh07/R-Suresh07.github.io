## Introduction

An agent harness is everything that surrounds the model: the tools it can call, the state it can see, and how its observations arrive. Solving a task with an agent therefore involves two decision procedures rather than one. While the model decides what to do with the information it receives, the harness decides what information reaches the model at all, including what gets remembered, what gets compacted away, and which actions it can even take.

The two are optimized very differently. The model's procedure is learned through training, while the harness's procedure is still commonly written by hand. It relies on a developer's "taste," built up from previous experience of what has gone wrong and what could go wrong in the future. This process is often cumbersome and time-consuming, since you have to run the loop of analyzing trajectories → analyzing failure modes → hypothesizing optimizations → rolling out, and then repeat.

This raises the question: why even bother? How much of what the harness does is work the model could do itself? We think the useful framing is not how much harness engineering can be automated, but how little is needed before the returns run out and further gains must come from the model’s policy. Ultimately, how far does harness engineering take you, and can we reach that limit without doing it by hand?

Our testing ground is the Small Molecule Drug Discovery (SMDD) Bench, a benchmark for challenging, multi-turn, long-horizon agentic tasks focused on small-molecule design. While LLMs have become very good at coding and math, which are easily and cheaply verifiable domains, generative chemistry provides a strong stress test. It serves as an underexplored task in a domain with an expensive and semi-verifiable verifier.<Sidenote number="1">Boltz-2 lets us estimate whether a molecule is likely to bind to a protein without running a physical experiment. It's much cheaper than traditional simulation methods, but its predictions are still imperfect and can vary across protein targets.</Sidenote> A task instance is also more than just a text prompt: the agent receives a 3D protein structure, information about where the relevant binding pocket is, and, for some tasks, the 3D position of part of a molecule. None of this is naturally easy for a language model to interpret, so what the agent knows about the pocket depends heavily on what its tools compute and how that information is presented back to it.

The implementation can stay compact. Build-time rendering gives the page highlighted code without sending a client-side syntax highlighter:

```ts
type Observation = { predicted: number; observed: 0 | 1 };

export function squaredLoss(sample: Observation) {
  return (sample.predicted - sample.observed) ** 2;
}
```

> **Interpretation note.** A lower aggregate loss is useful only when the evaluation set represents the decisions the system will actually encounter. Treat a clean metric as evidence, not as a conclusion.
